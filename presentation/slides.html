The brief

What I set out to build

The problem. As a content creator I was answering the same questions in every enquiry — what do you charge, what's included, when do I pay, what do I get. Each conversation started from zero.

The goal. A single website that presents my work, states my terms clearly, and lets a brand book me without a single back-and-forth message.

  • Show the portfolio — video, photography and voice
  • Explain services and pricing without ambiguity
  • Capture a complete brief in one submission
  • Serve both English and Malay speakers
  • Work on any device, for any level of ability
  • Use no JavaScript whatsoever

NBStructure04

The core constraint

Why no JavaScript?

The requirement was HTML and CSS only. Rather than treat that as a limitation, I used it as a design discipline.

  • Faster — nothing to download, parse or execute
  • More reliable — no script can fail and break the page
  • More accessible — works with scripting disabled
  • More secure — no script means no script-based attack surface

What still had to work:

  • An image carousel
  • Tabbed content panels
  • Scroll-triggered animation
  • A validated multi-field form
  • Language switching

Every one was solved in pure CSS.

NBConstraint05

Technique 01

Carousel without JavaScript

Hidden radio buttons hold the state. Clicking a <label> checks its radio, and the CSS sibling combinator ~ slides the track.

Six slides, previous and next arrows that rebind at each position, and an indicator that tracks the active slide — all from one CSS property changing.

/* the radio holds the state */
#s2:checked ~ .track {
  transform: translateX(-16.67%);
}

/* the label becomes the button */
<label for="s2"></label>
NBTechnique06

Technique 02

Tabbed panels without JavaScript

The payment page needs five methods — FPX, debit card, QR Pay, Stripe, Payoneer — each with different instructions.

Same radio principle: only the panel matching the checked radio is set to display:block. The rest stay hidden. The active tab is highlighted with the same selector.

/* show only the matching panel */
#pay3:checked ~ .panels
  .panel:nth-child(3) {
  display: block;
}
NBTechnique07

Technique 03

Scroll-driven animation

Content fades and rises as it enters the viewport, and grid items stagger so cards arrive in a wave.

This uses animation-timeline: view() — a modern CSS feature that drives an animation from scroll position rather than from a timer. Historically this required JavaScript.

/* progress driven by scroll */
.card {
  animation: revealUp linear both;
  animation-timeline: view();
  animation-range: entry 4% cover 26%;
}

Safety: wrapped in @supports so unsupporting browsers show content normally, and in prefers-reduced-motion so it respects accessibility settings.

NBDesign09

Localisation

Bilingual — English & Bahasa Melayu

The decision. A CSS show/hide toggle was possible, but it would reset to English on every page change. Instead each page has a full translated twin.

The switcher links to the matching page, so language persists as the visitor browses.

Each page declares lang="en" or lang="ms" so screen readers pronounce correctly.

Translation approach:

  • Full translation, not just headings — forms, terms, contracts included
  • Industry terms kept in English where Malaysian creators use them: UGC, KOL, hook, deliverable
  • Everything needed to make a decision is in Malay: pricing, percentages, terms

Accessibility

Designed to be usable by everyone

👁️

Contrast

Form fields measured at 19.3:1, labels at 7.6:1. WCAG AAA requires 7:1 — both exceed it.

⌨️

Keyboard

Visible 3px focus ring on every interactive element. The whole site is navigable by keyboard alone.

🎬

Motion

prefers-reduced-motion disables all animation for users who experience motion sickness.

A real problem I found and fixed: the booking form sat on a dark background, but native dropdown lists are drawn by the operating system and do not inherit page styling — producing dark text on a dark list. The fix was giving the form its own light card, guaranteeing dark-on-white for every option.

NBDocuments13

Problems solved

Challenges along the way

1 · Invisible content risk. Scroll animations start elements at zero opacity. If the animation never completes, content stays invisible. I tested all 163 animated elements across every page and found one stuck at 68% — an element in the hero that never fully traversed its range. Fixed by excluding above-the-fold content.

2 · A transparent colour. A mistyped 8-digit hex value made a gradient 28% transparent, washing out the dark sections. Caught by inspecting computed styles rather than trusting the eye.

3 · Dropdowns on dark backgrounds. Native form controls are rendered by the operating system and ignore page styling — solved by restructuring rather than fighting it.

4 · Print stripping colour. Browsers discard backgrounds when printing by default. Solved with print-color-adjust:exact.

5 · Language persistence. Solved architecturally with mirrored pages rather than a toggle.

NBChallenges14

Reflection

What I learned

CSS is more capable than expected

State management, tabs, carousels and scroll animation are all achievable declaratively. The constraint pushed me toward techniques I would not otherwise have found.

Test what you cannot see

The 68%-opacity bug and the transparent hex were both invisible to casual inspection. Measuring computed values caught what looking could not.

Design serves the business

The prettiest version of the booking form was unusable. Accessibility and clarity had to outrank aesthetics where the two conflicted.

"A website that looks beautiful but loses a booking has failed."
